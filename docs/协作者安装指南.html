给协作者：照着做，每步都有「怎么算成功」。卡在哪一步就把那步的输出发我。

预计耗时 40–60 分钟，其中一半时间在等下载。

0. 全流程速览

确认游戏本体 → 装 Git/LFS → clone 仓库 → 跑脚本定位游戏 → 装 BepInEx
→ 装 .NET SDK → 编译 → 进游戏看日志 → 完成

任何一步失败不要往下跳。后面所有步骤都建立在前面成功的基础上。

1. 前置清单

项目 要求 怎么确认
操作系统 Windows 10 / 11 x64 —
游戏本体 Steam 版 Crown Siege（正式版） Steam 库里能启动
Git 2.40+ git --version
Git LFS 任意版本 git lfs version
.NET SDK 8.0 或更高（本机实测 10.0.403 可用） dotnet --list-sdks
GitHub 账号 需要被加入仓库协作者 能打开仓库页面
反编译工具 ILSpy（免费） 见第 8 步
磁盘 游戏 5 GB + 工具 2 GB —

没有游戏本体做不了这件事。 这个 mod 依赖直接引用游戏本机的 Assembly-CSharp.dll，仓库里不包含它（也不允许包含）。

2. 第 1 步：确认游戏路径

默认路径通常是：

D:\SteamLibrary\steamapps\common\Crown Siege

不确定就按这个顺序找：

  1. Steam 客户端 → 库 → 右键 Crown Siege → 管理 → 浏览本地文件
  2. 或者看 C:\Program Files (x86)\Steam\steamapps\libraryfolders.vdf，里面列了所有库目录

成功的标志：这个路径下存在以下文件

Crown Siege\
├─ CrownSiege.exe
└─ CrownSiege_Data\
    ├─ Managed\Assembly-CSharp.dll      ← 必须有这个
    └─ boot.config                       ← 里面有 build-guid

把 boot.config 用记事本打开，找到 build-guid= 那一行。应该等于：

d07d7b203ec34f6b9a35c7796923a472

如果不一样 —— 说明你的游戏版本比我们的目标版本新/旧。先别往下做，告诉我实际值。

3. 第 2 步：装 Git 与 Git LFS

winget install --id Git.Git -e
# 装完关掉终端重开一个，让 PATH 生效
git --version
git lfs install

git lfs install 的输出应该是 Updated Git hooks.。这一步只做一次，全局生效。

配置身份（用你自己的名字和邮箱）：

git config --global user.name "你的名字"
git config --global user.email "你的邮箱"

成功标志：git --version 和 git lfs version 都能打出版本号。

4. 第 3 步：拿代码

仓库地址会单独发给你。私有的，需要你先接受邀请。

cd D:\Projects          # 换成你自己的目录
git clone <仓库地址，我会单独发你>
cd 06_CsMod
git lfs pull

成功标志：目录里能看到 src\、tools\、docs\、game-version.txt。

常见坑：git lfs pull 输出大量 Could not resolve → 你没装 LFS，回第 2 步。仓库里的 .png/.psd 会变成几十字节的文本指针文件，打开就是一行 version https://git-lfs...。

5. 第 4 步：让工程找到你的游戏

仓库里不带游戏路径，因为每个人安装位置不一样。用脚本自动探测：

powershell -ExecutionPolicy Bypass -File tools\detect-game.ps1

正常输出长这样：

[1/4] searching for Crown Siege ...
      found: D:\SteamLibrary\steamapps\common\Crown Siege
[2/4] checking game build fingerprint ...
      build-guid OK (d07d7b203ec34f6b9a35c7796923a472)
[3/4] Assembly-CSharp.dll = 1140224 bytes (Unity 6000.6.7f1 expected)
[4/4] writing local.props ...
      written: ...\06_CsMod\local.props

自动探测失败时，手动指定路径：

powershell -ExecutionPolicy Bypass -File tools\detect-game.ps1 -GameHome "E:\你的路径\steamapps\common\Crown Siege"

成功标志：仓库根目录出现 local.props，里面写着你的游戏路径。

local.props 已被 .gitignore 排除，永远不会被提交。它是你本机的私有配置，改了不用管。

6. 第 5 步：装 BepInEx（关键步骤）

这一步会修改你本地的游戏目录。只影响你自己这台机器，但要知道它在干什么。

6.1 下载

打开 https://builds.bepinex.dev/projects/bepinex_be，下载这一行（x64、Mono）：

BepInEx-Unity.Mono-win-x64-6.0.0-be.xxx+xxxxxxxx.zip

认准 Unity.Mono 和 win-x64。 别下 IL2CPP 版本（这个游戏是 Mono，下了会加载失败）。

6.2 安装

把 zip 解开，内容直接覆盖到游戏根目录，和 CrownSiege.exe 同一层。不是解到子文件夹。

解压后根目录大致多出：

Crown Siege\
├─ winhttp.dll              ← 注入器
├─ doorstop_config.ini      ← 注入配置
└─ BepInEx\
    ├─ core\
    ├─ plugins\             ← 我们的 dll 放这里
    └─ config\

（具体文件以你下的那个包为准。）

6.3 验证

从 Steam 启动游戏一次，进到主菜单，然后退出。

成功标志：真的能进游戏（没崩），并且出现

Crown Siege\BepInEx\LogOutput.log

打开这个日志，开头能看到 BepInEx 的版本号和预加载器信息。

如果游戏启动直接闪退：删掉 winhttp.dll 和 doorstop_config.ini 就能恢复原状，然后把日志发我。

7. 第 6 步：装 .NET SDK 并编译

winget install --id Microsoft.DotNet.SDK.8 -e
# 关掉终端重开
dotnet --list-sdks

装完提示「dotnet 不是内部或外部命令」= 终端没重开，PATH 还是旧的。关掉所有终端窗口再开一个。 还不行就直接用完整路径：& "C:\Program Files\dotnet\dotnet.exe" --list-sdks

编译：

cd <仓库目录>
dotnet build src\Mod.csproj -c Debug

成功标志：最后一行是 Build succeeded，并且出现

已部署到 ...\BepInEx\plugins\CrownSiegeToolkit\CrownSiegeToolkit.dll

如果报「未配置游戏路径」→ 回第 4 步。 如果报「找不到类型或命名空间 BaseUnityPlugin」→ 打开 src\Mod\Plugin.cs，把第一行 using BepInEx.Unity.Mono; 改成 using BepInEx;，重新编译。这是 BepInEx 5 与 6 命名空间差异，一行的事，告诉我一声我把仓库里的改掉。

8. 第 7 步：冒烟测试（P0）

这一步是整个环境是否可用的唯一判据。

从 Steam 启动游戏，进主菜单，然后打开：

<游戏目录>\BepInEx\LogOutput.log

必须同时看到这五行（顺序大致如下，中间会插进诊断信息）：

[Info  :Crown Siege Toolkit] Crown Siege Toolkit v0.1.0 loading ...
[Info  :Crown Siege Toolkit] [版本] build-guid 匹配 (d07d7b203ec34f6b9a35c7796923a472)
[Info  :Crown Siege Toolkit] Harmony PatchAll ok
[Info  :Crown Siege Toolkit] [P0] Harmony injected
[Info  :Crown Siege Toolkit] Crown Siege Toolkit ready. features=4/4

五行的含义：

日志行 证明什么
loading BepInEx 找到了我们的 dll 并加载
build-guid 匹配 你的游戏版本和项目锁定的版本一致
PatchAll ok Harmony 工具链通了
[P0] Harmony injected 补丁真的进了运行时，不是「加载了但没生效」
ready. features=4/4 四个模块（诊断/菜单/操控/联机）都注册成功

另外这段也是正常的，说明菜单探针在工作：

[菜单探针] Assembly-CSharp 共 xxxx 个类型，命中 xx 个候选：

只有 loading 没有 [P0] = 插件加载了但补丁没打上，这是最坑的半成功状态。出现这种情况把完整日志发我。

打到了，环境就配好了。

9. 第 8 步：装反编译工具

winget install --id ICSharpCode.ILSpy -e

用它打开 <游戏目录>\CrownSiege_Data\Managed\Assembly-CSharp.dll，就能读到全部游戏逻辑。

规则：

  • 反编译出来的代码只用来读，用来搞清楚类名、方法签名、调用链。
  • 不要把反编译结果整份提交进仓库，也不要把游戏代码抄进我们的工程。
  • 需要记录结论就写进 docs/RESEARCH.md：类名、方法签名、你的推断。

10. 日常怎么干活

git switch main
git pull --rebase
git lfs pull

git switch -c feat/你做的功能名

# 改代码 → 编译 → 进游戏验证

git status                       # 看一眼，确认没混进垃圾文件
git add <你改的文件>
git commit -m "feat(模块): 做了什么，为什么"
git push -u origin feat/你做的功能名

然后开 Pull Request，等 review，合并后删分支。

提交前必须做过的三件事（做不到就别提 PR）：

  1. 关掉游戏重开三次，现象一致（排除初始化竞态）。
  2. 日志里有关键值的断言输出，不是靠眼睛看画面。
  3. 删掉 BepInEx\plugins\CrownSiegeToolkit\ 能干净回到原状。

11. 绝对不要做的事

  1. 不要改游戏原始文件。CrownSiege_Data 里的东西一律不动，Steam 校验会覆盖它们，你改了也白改，还会让自己环境跟别人不一样。
  2. 不要把游戏 dll 或游戏资源提交进 Git。版权问题，而且会让仓库没法公开。
  3. 不要提交 local.props。那是你本机路径，别人拉下来会直接编译失败。
  4. 不要在 main 上直接改（探针实验除外，实验完立刻说）。
  5. 不要动别人 assets\ 下的文件。要改先加 LFS 锁，用完解锁。
  6. 不要攒几天不推。二进制没法 merge，你攒得越久，冲突越无解。

12. 排错表

现象 原因 处理
启动游戏闪退 BepInEx 装错版本（下了 IL2CPP 包） 删 winhttp.dll + doorstop_config.ini，换 Unity.Mono-win-x64 重来
没有 LogOutput.log BepInEx 没加载 确认 winhttp.dll 在游戏根目录、和 exe 同层
日志里没有我们的 mod dll 没放对位置 必须在 BepInEx\plugins\CrownSiegeToolkit\ 下
编译报「未配置游戏路径」 local.props 不存在 跑 tools\detect-game.ps1
编译报找不到 Assembly-CSharp 路径指错或游戏没装全 detect-game.ps1 -GameHome "实际路径"
编译报 BaseUnityPlugin 不存在 命名空间差异 Plugin.cs 首行改成 using BepInEx;
图片打不开、只有一行文字 LFS 没拉 git lfs install + git lfs pull
提示 build-guid mismatch 游戏版本和我们对不上 别继续，把实际值发我
改了没效果 补丁没命中 看日志有没有 [P0] Harmony injected

13. 怎么恢复原状

# 1. 移除我们的插件
Remove-Item -Recurse -Force "<游戏目录>\BepInEx\plugins\CrownSiegeToolkit"

# 2. 彻底卸载 BepInEx（回到干净游戏）
Remove-Item "<游戏目录>\winhttp.dll"
Remove-Item "<游戏目录>\doorstop_config.ini"
Remove-Item -Recurse -Force "<游戏目录>\BepInEx"

# 3. 让 Steam 校验一遍，确保游戏文件完好
#    Steam → 库 → 右键 Crown Siege → 属性 → 已安装文件 → 验证文件完整性

这三步做完，游戏和没装过一样。

14. 第一天 checklist

  • 游戏能启动，Assembly-CSharp.dll 存在
  • build-guid 和文档一致（d07d7b...a472）
  • git --version / git lfs version / dotnet --list-sdks 三个都有输出
  • clone 成功，git lfs pull 无报错
  • detect-game.ps1 跑通，local.props 生成
  • BepInEx 装上，进游戏不崩，LogOutput.log 存在
  • dotnet build 成功，dll 自动落到 BepInEx\plugins\CrownSiegeToolkit\
  • 日志里五行全中，含 [P0] Harmony injected 和 ready. features=4/4
  • ILSpy 能打开 Assembly-CSharp.dll，能看到 ApplyDamageSystem

全打勾 = 环境可用。有任意一项没勾，先别写代码。
