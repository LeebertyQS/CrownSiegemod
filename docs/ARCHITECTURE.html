目标：让第二个人能在不看代码的情况下知道「东西放在哪、边界在哪、哪些事不能做」。

1. 分层

Plugin.cs                    入口：读配置 → 版本哨兵 → 注册模块 → 每帧驱动
  └─ Core/                   公共地基，不含任何玩法知识
       IModFeature           模块契约
       FeatureRegistry       模块注册与隔离（单模块崩了不连坐）
       ModSettings           BepInEx 配置集中管理
       VersionGuard          build-guid 哨兵
       ModLog                带级别的日志门面 + Once 断言
  └─ Diagnostics/            环境诊断（无副作用）
  └─ Menu/                   主菜单注入（定位中）
  └─ Control/                手动操控（骨架）
  └─ Net/                    联机（只有接口，故意不实现）

依赖方向单向且只有一条：模块 → Core。模块之间不互相引用。

Menu 要叫 Net 怎么办？通过 NetFeature.RequestOpenLobby() 这一个内部方法，不引 INetCode 的实现。这样联机方案怎么换，菜单都不用动。

2. 为什么是「单程序集 + 目录边界」，不是「一个模块一个 csproj」

多工程更「干净」，但这个游戏没有任何人被 mod 过（无 mod 目录、无 Workshop、无 BepInEx 痕迹）。在没验证过 BepInEx 6 的跨程序集解析行为之前就上多 DLL，等于给自己埋一个「插件加载顺序 / 依赖 DLL 找不到」的隐形地雷，而且这类问题的表现是"什么都没发生"，最难查。

所以：

需求 用目录解决 不用多工程
两人不冲突 一人一个目录，Plugin.cs 里各加一行 —
单独关掉 配置文件里 [Features] xxx=false —
单独崩掉 FeatureRegistry 逐个 try/catch —

Plugin.cs 的模块注册区是唯一会被两人同时改的地方，规则：只追加，不重排，一次一行。

4. 联机：为什么现在只写接口

「主菜单多一个联机选项」是两件事，必须先分开看：

部分 工作量 难度
菜单里加按钮 60 行 低，等探针结果
按钮后面真的有联机 数月 极高，且可能不成立

真联机要解决的三个问题，一个都绕不过：

① 状态怎么读出 ECS。 战场状态活在 ECS chunk 里，模拟在 Burst Job 里跑。没有 WorldSnapshot、没有 ISystem、没有任何为同步准备的序列化接口。要同步就得反射遍历 chunk 逐字段读，几百个实体 × 每秒多次 —— 性能代价未知，且每加一个组件就要改一次同步代码。

② 谁是权威。 这游戏是自动战斗 + 波次生成 + 随机解锁。主机算所有人？那客户端要发回每个操作；各自模拟 + 校正？先得有确定性。而 Burst Job 的浮点运算和调度顺序没有确定性保证，回滚式同步（rollback netcode）在这个底座上做不了。

③ 同步什么粒度。 整局状态 → 带宽爆炸。只同步指令 → 这游戏玩家几乎没有指令（它本来就是"看着打"）。只同步种子 + 输入 → 前提是确定性模拟，见 ②。

结论：联机不是"加个功能"，是"给一个单机游戏补一套确定性模拟层"。以 2 个人、当前日活两位数的盘子，这是最容易做成半成品的项目。

真要做，先答第 ② 个问题。答不上来就别写代码，写代码只是在错误方向上堆量。

5. 引擎选型：团结引擎、Godot 能不能用

运行时：都不能。只有 Unity 6000.6.7f1。

引擎 能不能 依据
Unity 6000.6.7f1 ✅ 唯一可行 游戏本体就是这个版本；AssetBundle 头里写着 5.x.6000.6.7f1，序列化格式必须对上
团结引擎（Tuanjie 1.x） ❌ 官方口径：以 Unity 2022 LTS 为研发基础、独立分支、版本节奏与 Unity 不一致。它烘出的资源头会是 2022.x，塞给 6000.6 的游戏要么被拒、要么字段错位
Godot 4.x ❌ 完全不同的引擎实现，产不出 UnityFS bundle，也无法注入 Mono 程序集

但要分清楚两件事：「运行时」不行 ≠ 「一点都用不上」。

场景 能用什么
代码注入、patch、联机逻辑 只能 C# + BepInEx（Unity 6000.6 的托管层）
烘 bundle / 重烘 ECS 子场景 只能 Unity 6000.6.7f1 编辑器（目前没装，是"加内容"的头号门槛）
外部工具（配置编辑器、数据校验、关卡可视化、打包 GUI） 随便。Godot、Electron、Python 都行，只要不碰游戏运行时
我们自己的原创游戏项目 随便。工作室 03_MainGame 就是 Godot 4.7.2

一句话：团结和 Godot 都进不了这个 mod 的执行路径；Godot 最多做外围工具。

6. 「加内容」的前置条件（现在缺的）

要往游戏里加单位/关卡，需要：

  1. Unity 6000.6.7f1 编辑器（不是 6.0，不是 6.2，版本号要对上）
  2. 版本匹配的 Entities / Burst / Addressables 2.11.2 包
  3. 一个能重烘 EntityScenes/*.entities 的工程（游戏没提供源工程，要自己搭）
  4. 能重建 catalog.bin 或者躲开 Addressables 校验

这四条一条都不满足。所以"加内容"现在处于阻塞状态，"加机制"是唯一能动的方向。

这不是坏消息，是排期事实：先做机制，机制跑通了，再去啃工程重建。
